# Retention architecture for 20-45 s educational video

Timings are **starting hypotheses**. Test against the creator's own retention graphs (hook-analytics). Source basis: practitioner interviews (S49 Lawrence, S53/S54 MrBeast, S55/S56 Colin & Samir, S48 Hormozi) plus lab work on suspense/transportation (S17, S27). None of it was validated on 20-45 s feeds -> **Guess/Likely**.

## Anatomy (any architecture)
1. **Hook + premise** (0-3 s): the gap and why it concerns this viewer.
2. **Stakes / relevance** (1-2 beats, may be merged with 1): why knowing matters without fear.
3. **Minimal context** (<= 1 beat): only what the payoff needs.
4. **Evidence / demonstration** (core): show before telling where possible.
5. **Intermediate reveal** (1 per 10-15 s of video, if natural): a partial answer that sharpens the main question.
6. **Payoff** (never later than ~80% of runtime, hypothesis): answers the hook's exact question.
7. **Implication / practical conclusion**: what to do or understand now.
8. **Close**: one line; optional honest re-hook.

## Architecture A - Myth -> contradiction -> explanation -> practical conclusion
Beats: myth stated (with attribution) -> evidence contradicts (source on screen) -> mechanism -> what to do.
Optics example: glasses weaken eyes? (S35 myth 14; scope with S39). Failure: repeating the myth more than correcting it; correction scope too wide.

## Architecture B - Demonstration -> unexpected result -> mechanism -> takeaway
Beats: set up apparatus -> effect happens -> "why" -> safe replication / meaning.
Optics example: pinhole sharpens blur (S45, S46). Failure: the camera shows something the eye would not see (see hook-visual-design); effect too subtle in frame.

## Architecture C - Common belief -> evidence -> correction -> implication
Beats: belief -> study/figure -> corrected claim at evidence strength -> implication for behaviour.
Optics example: blue-light glasses and eye strain (S33, S34). Failure: evidence is a narrative review - do not present as a meta-analysis; overstate "nothing works".

## Architecture D - Problem -> overlooked cause -> demonstration -> resolution
Beats: recognisable problem -> cause the viewer has not considered -> show the cause -> the fix.
Optics example: eyes burn after long reels -> reduced blinking (S32) -> show blink counting -> 20-20-20 (S33). Failure: fix promises more than evidence.

## Architecture E - Question -> clues -> explanation -> final reveal
Beats: question -> clue 1 -> clue 2 -> explanation -> reveal. Use only if clues each narrow the possibilities. Failure: clues are decoration; reveal is anticlimactic.

## Architecture F - Micro-story -> conflict -> discovery -> meaningful lesson
Beats: moment of tension -> obstacle -> discovery -> lesson. Use "but / therefore" links, not "and then" (S56). Failure: invented anecdote; lesson unrelated to the story. Must be true or labelled composite.

## Open-loop ledger (fill per script)
| Loop | Opened at | Closed at | Worth the wait? |
|---|---|---|---|
Rules: exactly one primary loop; one secondary max; no loop open at the final line unless it is an explicit, honest invitation to the next video; every loop must be closed with information, not with another question.

## Diagnosing retention failures in the script (before publishing)
| Symptom (expected on graph) | Likely script cause | Fix |
|---|---|---|
| early cliff | promise unclear or already answered; packaging mismatch (S03, S50) | restate gap; align first frame and hook |
| steady slope after beat 2 | repetition / no progression | cut or merge beats; add intermediate reveal |
| drop right after payoff | "got what they came for" (S50) | place a genuine second question before/at the payoff; shorten tail |
| late drop at close | "shut up and finish" wind-down (S50) | end on value; trim outro |
| payoff complaint in comments | promise > delivery | rewrite hook to what is delivered |

(Graph interpretation is from creator practice and YouTube's retention help, S03; verify on your data.)

## Ending rules
- Respect the viewer's time: stop after the value.
- A loop back to the first sentence is good only if it re-frames the opening; never to hide that the payoff was thin.
- A call to action is allowed only if the creator requests it; never a product or paid offer.
