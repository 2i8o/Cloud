# Retention architecture

Retention is earned by progression, not by repetition or withholding. Every beat must either **answer** something, **sharpen** the question, or **open one new justified question**.

## Procedure
1. State the **promise** in one sentence (what the hook implies the viewer will learn/see).
2. Choose an architecture (`references/retention-architecture.md`): A Myth -> contradiction -> explanation -> practical conclusion; B Demonstration -> unexpected result -> mechanism -> takeaway; C Common belief -> evidence -> correction -> implication; D Problem -> overlooked cause -> demonstration -> resolution; E Question -> clues -> explanation -> reveal; F Micro-story -> conflict -> discovery -> lesson. These are starting patterns; adapt or abandon if the idea fits none.
3. Build the **beat sheet**: for each beat, write `purpose | new information | thread status (opens/sharpens/closes) | visual | approx seconds`. Seconds are hypotheses.
4. Run the **thread audit**: exactly ONE primary curiosity thread; at most ONE secondary thread, opened only if it will be closed before the end.
5. Run the **progress test** on every beat: "What does the viewer know after this beat that they did not know before?" If nothing, cut or merge.
6. Run the **payoff test**: does the final answer resolve the hook's question in the same terms? Is the payoff worth the wait (not cheaper than the withholding)?
7. Design the **ending**: one honest closing line; no padding or "wind-down" signal before value is finished; a re-hook only if the next video is genuinely the next question.

## Distinctions to enforce
| Do | Don't |
|---|---|
| progression: each beat adds | repetition: restating the premise louder |
| suspense: a clear stake the viewer can follow | confusion: unclear what is being asked |
| delay for the sake of a reveal | needless withholding of a simple answer |
| concise with needed context | missing context that makes the payoff meaningless |
| ending on the value | abrupt cut mid-resolution OR a slow wind-down |
| loop back to the first line when honest | loop that disguises an unanswered question |
| a satisfying answer | an incomplete explanation presented as the whole story |

## Tensions between sources (do not collapse)
- Lawrence: do not give away your most valuable content at the start (S51). Leavitt & Christenfeld: knowing outcomes did not spoil short stories (S27). **Working rule [Guess]:** the *what* may be stated early; the *why/how/demo* is the payoff. Test it.
- Lawrence: when a viewer's key question is answered, they may leave - set up another question before/at that moment (S49 ~00:20). Fine for 45 s only if the new question is real.
- MrBeast: you "don't have to try as hard" late in a video because longer watching predicts continued watching (S54, ~00:32); applies to long-form retention curves. For 20-45 s, the first beats still decide whether a second beat exists. Do not import 70% retention targets (S53) - YouTube publishes no benchmark; use your own baseline (hook-analytics).

## Output
Per finalist: promise, architecture, beat table, thread audit (primary/secondary), payoff check, ending line, risks. Keep to <= 12 lines per finalist in the creator view.
